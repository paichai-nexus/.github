## NEXUS는 어떤 동아리인가요?

PAICHAI NEXUS는 배재대학교의 여러 전공 학생들이 함께 문제를 찾고, 각자의 전공을 활용하여 실제 결과물을 만드는 학생 주도 융합 프로젝트 동아리입니다.

처음부터 많은 기술을 알고 있거나 코딩을 잘해야 하는 것은 아닙니다. 아직 경험이 부족하더라도 다른 학생들과 함께 조사하고, 배우고, 직접 만들어보는 과정을 중요하게 생각합니다.

컴퓨터공학과 학생만 참여하는 동아리도 아닙니다. 프로젝트에 따라 소프트웨어, 전기전자, 원예산림, 드론로봇, 건축, 조경, 디자인, 식품영양, 외식조리 등 여러 전공의 학생들이 함께할 수 있습니다.

NEXUS가 가장 중요하게 생각하는 것은 다음 세 가지입니다.

1. 작은 목표라도 끝까지 완성하기
2. 결과뿐 아니라 배우고 실패한 과정도 기록하기
3. 다음 사람이 이어갈 수 있도록 자료를 남기기

많은 프로젝트를 동시에 시작하기보다 한 학기에 가장 중요한 프로젝트를 정하고, 실제 결과물이 나올 때까지 집중합니다.

2026년 2학기에는 **Smart Seedling AI를 가장 중요한 프로젝트로 정하고 연구개발과 제작에 집중**합니다.

## 주요 활동

NEXUS는 크게 두 가지 활동을 진행합니다.

### 1. 연구개발

서로 다른 전공의 지식을 연결해 실제 문제를 조사하고, 직접 만들거나 실험하면서 해결 방법을 찾아갑니다.

- 비슷한 논문과 기존 제품 찾아보기
- 해결할 문제를 구체적으로 정하기
- 필요한 자료와 데이터 수집하기
- 소프트웨어·센서·AI·설계 등을 활용해 결과물 만들기
- 만든 기능이 제대로 작동하는지 확인하기
- 실험 과정과 결과를 문서로 남기기

처음부터 전체 시스템을 완성하려고 하지 않습니다. 먼저 한 학기 안에 만들 수 있는 작은 기능을 정하고, 실제로 작동하는 결과물을 만드는 것부터 시작합니다.

새로운 기술을 사용했다는 사실보다 다음 질문에 답할 수 있는 프로젝트를 만들고자 합니다.

- 어떤 문제를 해결하려고 했는가?
- 기존 방식은 어떻게 작동하는가?
- 우리는 무엇을 추가하거나 바꾸려고 했는가?
- 직접 만들어보니 무엇이 됐고 무엇이 안 됐는가?
- 다음에는 무엇을 개선해야 하는가?

### 2. 프로젝트·공모전·전시

프로젝트에서 만든 결과물을 다른 사람에게 보여주고 평가받는 활동입니다.

- 교내외 공모전과 아이디어 경진대회 참여
- 해커톤과 프로젝트 발표 참여
- 전시와 체험 부스 운영
- 학교와 지역사회의 문제를 해결하는 서비스 제작
- 프로젝트 발표자료와 시연 영상 제작
- 코드·설계·조사·실험 결과를 포트폴리오로 정리

수상만을 목표로 하지는 않습니다. 정해진 기간 안에 역할을 나누어 결과물을 완성하고, 받은 의견을 다음 작업에 반영하는 경험을 중요하게 생각합니다.

### 한 번에 하나씩 완성합니다

NEXUS는 아이디어가 생겼다고 여러 프로젝트를 동시에 시작하지 않습니다.

```text
문제 발견
→ 비슷한 사례 조사
→ 작은 목표 설정
→ 참여자와 역할 결정
→ 제작과 실험
→ 결과 기록
→ 발표 또는 다음 단계 결정
```

책임자와 참여자, 첫 번째 목표가 정해지지 않은 아이디어는 바로 시작하지 않고 내부 제안 목록에 보관합니다.

```text
아이디어 → 조사 → 팀 구성 → 제작 → 확인 → 기록
```

## 2026년 가장 중요한 프로젝트

### 🌱 [Smart Seedling AI](https://github.com/paichai-nexus/smart-seedling-ai)

> 작물 이미지와 환경 데이터를 모아 생육 상태를 관찰하는 스마트팜 프로젝트

Smart Seedling AI는 작물의 이미지와 온도·습도 같은 환경 정보를 수집하고, 이를 한 화면에서 확인할 수 있도록 만드는 프로젝트입니다.

앞으로 데이터가 충분히 모이면 이미지 분석 AI를 활용해 작물의 생육 상태나 이상징후를 찾는 기능으로 발전시키고자 합니다.

### 2026년 2학기 첫 번째 목표

1. 대상 작물을 정합니다.
2. 작물 이미지를 일정한 방식으로 촬영합니다.
3. 온도와 습도 등 기본적인 환경 정보를 수집합니다.
4. 수집한 정보를 저장합니다.
5. 웹 화면에서 이미지와 환경 정보를 확인합니다.
6. 실험 과정과 결과를 문서로 남깁니다.

### 전공별 역할

| 분야 | 함께할 수 있는 일 |
| --- | --- |
| 원예산림 | 대상 작물 선정, 생육 기준 정리, 실험 결과 확인 |
| 컴퓨터공학·소프트웨어 | 데이터 처리, 이미지 분석, 웹 화면 제작, 시스템 연결 |
| 전기전자 | 환경센서, 전원, 배선, 제어 장치 구성 |
| 드론로봇 | 촬영 방법과 자동화 적용 가능성 조사 |
| 건축·조경 | 온실, 재배공간, 식재환경과 이동 동선 검토 |
| IT경영정보 | 일정, 회의록, 예산과 활동 결과 정리 |
| 디자인·콘텐츠 | 프로젝트 소개자료, 발표자료와 사용 화면 디자인 |

사용자가 식재료를 촬영하면 종류와 상태를 확인하고, 먼저 사용해야 할 재료와 만들 수 있는 음식을 추천하는 기능을 생각하고 있습니다.

컴퓨터가 추천한 결과를 그대로 사용하는 것이 아니라, 외식조리학과 학생이 실제로 조리해보고 식품영양학과 학생이 영양과 안전성을 확인합니다.

```text
식재료 촬영
→ 식재료 종류와 상태 확인
→ 먼저 사용할 재료 판단
→ 만들 수 있는 음식 추천
→ 외식조리학과의 실제 조리와 수정
→ 식품영양학과의 영양·안전 확인
→ 사용자 의견 반영
```

현재는 참여자, 비슷한 사례, 첫 실험 범위와 학과별 역할을 정리하는 준비 단계입니다. 책임자와 첫 번째 결과물이 정해진 후 실제 진행 여부를 결정합니다.

## 프로젝트 진행 방법

### 1. 비슷한 사례부터 찾아봅니다

아이디어가 생기면 바로 개발하지 않습니다. 먼저 비슷한 논문, 제품, 다른 학교 프로젝트와 공개자료를 찾아봅니다.

### 2. 작은 결과물부터 만듭니다

한 달 또는 한 학기 안에 실제로 만들 수 있는 작은 기능이나 실험부터 시작합니다.

- 센서 한 종류 연결하기
- 작물 이미지 100장 수집하기
- 웹 화면에 온도와 습도 표시하기
- 제한된 식재료 다섯 종류 인식하기
- 공간 평면도와 장비 배치안 만들기

### 3. 담당자를 명확하게 정합니다

모든 과제에는 담당자와 마감일을 정합니다. 진행이 어렵다면 마감일이 지난 뒤가 아니라 미리 공유하고 함께 조정합니다.

### 4. 진행 상황을 솔직하게 기록합니다

| 상태 | 의미 |
| --- | --- |
| `아이디어` | 아직 생각을 정리하는 단계 |
| `준비 중` | 책임자, 참여자와 첫 목표를 정하는 단계 |
| `진행 중` | 실제 조사·개발·설계·실험을 진행하는 단계 |
| `확인 중` | 만든 결과물이 제대로 작동하는지 확인하는 단계 |
| `완료` | 결과물과 활동 기록을 정리한 상태 |
| `보류` | 필요한 조건이 갖춰질 때까지 기다리는 상태 |

프로젝트가 보류됐다고 해서 실패한 것은 아닙니다. 준비가 됐을 때 다시 시작하기 위한 선택입니다.

## GitHub·Notion·Discord는 어떻게 사용하나요?

### GitHub

GitHub에는 프로젝트 코드와 기술자료를 기록합니다.

- 프로그램 코드
- 센서와 장비 설정 방법
- 설치 및 실행 방법
- 기능별 작업 내역
- 오류와 해결 과정
- 프로젝트 결과물

처음부터 모든 기능을 알 필요는 없습니다. 프로젝트에 필요한 기능부터 단계적으로 배웁니다.

### Notion

Notion에는 프로젝트 계획과 회의 내용을 자세히 기록합니다.

- 회의 날짜와 참석자
- 논의한 내용
- 결정된 내용
- 아직 결정되지 않은 내용
- 담당자와 마감일
- 다음 회의에서 확인할 내용

### Discord

Discord에는 공지와 회의 결과를 짧게 공유합니다.

- 무엇이 결정됐는지
- 각자 무엇을 해야 하는지
- 언제까지 해야 하는지
- 자세한 내용을 어디에서 확인하는지

처음 참여한 부원들이 궁금한 점을 남길 수 있도록 질문 공간과 자주 묻는 질문 안내도 운영합니다.

## AI 도구 사용 원칙

NEXUS는 AI 도구의 사용을 무조건 금지하지 않습니다. 다만 AI가 만든 결과를 이해하지 못한 상태로 그대로 제출하는 것은 프로젝트 참여로 인정하지 않습니다.

1. 사용한 코드와 문서를 본인이 설명할 수 있어야 합니다.
2. AI가 만든 내용이 맞는지 직접 확인해야 합니다.
3. 오류가 발생하면 원인을 찾아 수정해야 합니다.
4. 중요한 기능은 기술과 작동 원리를 함께 공부해야 합니다.
5. 다른 사람의 코드, 이미지와 문서는 출처와 이용 조건을 확인해야 합니다.
6. 개인정보, 비밀번호, 인증키와 공개하면 안 되는 자료를 AI에 입력하지 않습니다.

학교 수업에서는 프로그래밍 언어와 기본 문법을 배우고, 동아리에서는 이미지 분석, 센서 연결, 웹 화면 제작, GitHub 사용처럼 프로젝트에 추가로 필요한 내용을 함께 익힙니다.

빠르게 결과를 만드는 것보다 자신이 무엇을 만들었고 왜 작동하는지 이해하는 것을 우선합니다.

## 부서 팀장과 활동 분야

NEXUS는 프로젝트에 필요한 역할을 다음과 같은 분야로 나누어 운영합니다.

현재 모든 분야를 독립된 부서로 운영하는 것은 아닙니다. 진행 중인 프로젝트와 실제 참여 인원에 따라 필요한 담당자와 팀을 구성합니다. 직책과 부서의 수를 늘리는 것보다 실제로 맡을 사람과 결과물이 있는지를 먼저 확인합니다.

### 분야별 담당자

| 활동 분야 | 담당자 |
| --- | --- |
| 기획·전략 | 김승조 · 임시 팀장 |
| 프로젝트 운영 | 남궁예광 · 임시 팀장 |

임시 팀장은 해당 분야의 첫 업무와 운영 방법을 정리하는 역할입니다. 일정 기간 활동한 뒤 실제 수행 내용, 결과물과 참여 의사를 확인하여 역할 유지 또는 조정 여부를 결정합니다.

### 기획·전략

학생들의 아이디어를 정리하고 프로젝트의 목표와 진행 범위를 함께 설정합니다. 새로운 아이디어가 실제로 진행 가능한지 검토하고 동아리의 우선순위를 정합니다.

### 프로젝트 운영

프로젝트별 담당자, 일정, 진행 상황과 결과물을 관리합니다. 진행이 어려운 부분을 미리 확인하고 팀이 정한 목표를 끝까지 완성할 수 있도록 돕습니다.

### 연구·개발

AI, 소프트웨어, 하드웨어, 데이터, 센서와 임베디드 등 프로젝트에 필요한 기술을 공부하고 실제 결과물을 제작합니다.

### 디자인·소통

UX·UI, 공간 및 제품 디자인, 발표자료, 포스터와 SNS 콘텐츠를 제작합니다. 프로젝트의 내용이 다른 사람에게 쉽고 정확하게 전달되도록 돕습니다.

### 대외협력

교수님, 학교 부서, 기업, 기관 및 다른 대학과의 상담과 협력을 진행합니다. 필요한 자문과 외부 활동 기회를 프로젝트에 연결합니다.

### 운영지원

예산, 구매, 물품, 회원 정보와 각종 행정자료를 관리합니다. 동아리 활동에 필요한 자원이 투명하게 사용되고 기록될 수 있도록 지원합니다.

### 교육·행사

부원 간 스터디와 전공 멘토링을 운영하고, 교육 프로그램, 체험행사, 전시와 부스 운영에 필요한 자료와 진행 방식을 준비합니다.

### 인문사회·사용자 연구

법, 정책, 윤리, 심리와 사용자 관점에서 프로젝트를 검토합니다. 개인정보와 저작권을 확인하고 실제 사용자에게 필요한 결과물인지 조사합니다.

- 임원, 부서 팀장, 관리자와 프로젝트 TF 팀장은 서로 다른 역할입니다.
- 임원은 동아리의 방향과 운영 기준을 정하고 담당 분야를 관리합니다.
- 부서의 임시 팀장은 맡은 활동 분야의 첫 업무를 구성하고 임원에게 진행 상황을 공유합니다.
- 관리자는 Discord와 회계처럼 동아리 운영에 계속 필요한 특정 업무를 책임집니다.
- 프로젝트 TF 팀장은 개별 프로젝트가 목표한 결과물까지 완성되도록 팀을 이끕니다.
- 새로운 담당자는 먼저 한 달 동안 역할을 수행한 뒤 유지 여부를 함께 확인합니다.
- 활동이 어려워지면 미리 알리고 관련 자료와 업무를 다른 구성원에게 인수인계합니다.
- 맡은 역할을 성실하게 수행한 구성원은 이후 프로젝트 팀장이나 운영진으로 성장할 수 있습니다.

## 참여 안내

NEXUS는 배재대학교 재학생과 휴학생이라면 전공과 학년에 관계없이 참여할 수 있습니다.

현재 실력이 부족하다고 생각해도 괜찮습니다. 잘하는 사람만 모으기 위한 동아리가 아니라 서로 부족한 부분을 배우며 결과물을 만들어가기 위한 동아리입니다.

다음과 같은 학생과 함께하고 싶습니다.

- 자신의 전공을 실제 프로젝트에 적용해보고 싶은 학생
- 모르는 것을 질문하고 함께 배우고 싶은 학생
- 작은 역할이라도 약속한 기한을 지킬 수 있는 학생
- 코드뿐 아니라 설계·실험·디자인·문서·조사·운영에 참여하고 싶은 학생
- 실패하더라도 과정을 기록하고 다시 시도할 수 있는 학생
- 자신의 아이디어를 다른 학생들과 함께 발전시키고 싶은 학생

### 새로운 프로젝트를 제안하려면

1. 어떤 문제를 해결하고 싶은가?
2. 첫 번째로 무엇을 만들고 싶은가?
3. 본인은 어떤 역할을 맡을 수 있는가?
4. 어떤 전공과 도움이 필요한가?
5. 첫 한 달 동안 무엇을 할 수 있는가?

처음부터 완벽한 계획서를 만들 필요는 없습니다. 운영진과 함께 아이디어를 작은 목표로 구체화합니다.
